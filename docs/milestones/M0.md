## How facts were checked

A throwaway spike (not committed) ran on Linux (Ubuntu 24.04, .NET SDK 10.0.113, `Microsoft.AnalysisServices` and `AdomdClient` 19.118.3, `ModelContextProtocol` 2.3.0) against a tiny synthetic TMDL model.

| Check | Result |
|---|---|
| TOM package contents | Managed `net472`, `net6.0`, `net8.0` assemblies; no native binaries. Runs on .NET 10. |
| `TmdlSerializer.DeserializeDatabaseFromFolder` on Linux | ✅ Tables, columns, measures, M partitions, relationships, RLS roles all load. |
| In-memory load (`MetadataSerializationContext` + `ReadFromDocument` + `ToDatabase`) | ✅ Works from strings with logical paths, so Git blobs can be read without a checkout. Passing `null` options throws; use `MetadataDeserializationOptions.Default`. |
| TMSL round trip | ✅ after setting the database name (PBIP `database.tmdl` has none, and serialization fails on an empty name). |
| TMDL round trip to a folder | ✅, but **file names follow object names** (`roles/West.tmdl` → `roles/West Region.tmdl`). Write tools must edit files in place. |
| `TmdlSerializer.SerializeObject` | ✅ Per-object TMDL snippets (useful for diff before/after). |
| Error reporting | `TmdlFormatException` gives document + line + line text; unresolved references give `TmdlDeserializationWithReferenceErrorsException` with a list. |
| DAX dependency API in TOM | ❌ None, so we need our own DAX lexer and dependency graph. |
| Newer object types in TOM 19.118 | ✅ `Function` (DAX UDFs), `Calendar`, `CalculationGroup`, `QueryGroup`, `EntityPartitionSource`, `FormatStringDefinition`, `RefreshPolicy`; `LineageTag` present. |
| ADOMD/TOM → `powerbi://` with service principal (Linux) | Reached Entra ID (real AADSTS error for a fake app ID). |
| ADOMD → `powerbi://` without credentials (Linux) | "an external access-token is required": built-in interactive login unavailable. |
| ADOMD with external `AccessToken` (Linux) | Made the HTTPS request to `api.powerbi.com`; blocked by the sandbox proxy, so **not verified end to end**. |
| ADOMD/TOM → `localhost:port` (Linux) | ❌ `NotSupportedException`: "supported for a .NET Core client only on Windows systems". |
| MCP SDK 2.3 | Tool annotations (`ReadOnly`, `Destructive`, `Idempotent`, `OpenWorld`), structured content and output schemas, resources with URI templates, and prompts are all available. |

## Research findings

- **Microsoft BPA rules** (`microsoft/Analysis-Services`): MIT, 71 rules. **Tabular Editor community rules**: no license file, so not vendored. TE2: MIT.
- **Microsoft's local MCP server** is now called the **Power BI Authoring MCP Server**. npm 1.0.0 shipped 2026-09-25 with Windows, Linux and macOS binaries. Use is subject to a EULA despite the MIT repo license file.
- **.NET 8 support ends 2026-11-10**, so the design targets .NET 10 (ADR-0002).
- The NuGet package ID `TabularTools` is available.

## Decisions made

See the ADR index. The main ones: own read layer with Microsoft's server as an optional companion (0001), .NET 10 (0002), git CLI (0003), diff on object graphs with lineage-tag renames (0004), BPA-compatible rules (0005), differential measure tests with query-scoped overrides (0006), explicit lineage config (0007), read-only safety model (0008), our own token acquisition (0009).

## Known gaps / unverified

- **Live XMLA end to end**: not verified on any platform (no tenant; `api.powerbi.com` blocked from the build environment). M4 will include a manual verification script for Windows.
- **Query-scoped override semantics** (dependents pick up `DEFINE MEASURE`; `DEFINE COLUMN` on the service): to verify in M4.
- **License terms of `Microsoft.AnalysisServices` / `AdomdClient`** for redistribution in self-contained builds: the license URL couldn't be fetched (`go.microsoft.com` blocked). Must be confirmed before the first release.
- **GA status of Microsoft's Authoring MCP server**: couldn't be confirmed from Microsoft docs (`learn.microsoft.com` blocked). It doesn't affect the decision.
- **Build environment:** Microsoft's .NET download hosts are blocked, so the SDK came from Ubuntu's archive (`dotnet-sdk-10.0`). Future sessions can use the same route.
