# M1 — Skeleton

**Status:** Done, 2026-10-27.

## What was built

| Area | What |
|---|---|
| Solution | `TabularTools.slnx` with `Core`, `Mcp`, `Cli` and three test projects. `net10.0`, nullable on, warnings as errors, central package versions (`Directory.Packages.props`), SDK pinned in `global.json`. |
| Core: loading | `ModelLocator` resolves `.pbip` → report `definition.pbir` `byPath` → `*.SemanticModel`; also `*.SemanticModel` folders, TMDL `definition` folders, `model.bim`, and a folder holding exactly one of those. `ModelLoader` reads TMDL/TMSL with TOM 19.118.3, names the database after the folder (PBIP leaves it empty), and turns TOM errors into diagnostics with file and line. |
| Core: snapshot | Immutable `ModelSnapshot` with stable keys (`table:Sales/measure:Total Sales`; relationships keyed by endpoints). Covers tables (plain, calculated, calculation groups), columns, measures, partitions, hierarchies, calculation items, relationships, roles with RLS/OLS, M parameters/shared expressions, DAX functions, perspectives, cultures, and lineage tags. |
| Core: workspace | `ModelWorkspace` caches loaded models by content hash (SHA-256 of every definition file) and issues `m-…` handles. Edited models reload automatically. |
| Core: describe | `ModelDescriber` with `summary` / `objects` / `full` detail, filters (tables, object types, name glob, hidden), and opaque cursor paging. JSON, Markdown and text renderers. |
| MCP host | stdio server with `ping`, `open_model`, `describe_model`. Read-only annotations, output schemas, string enums in input schemas, a summary line plus JSON as text and structured content. Expected failures are tool errors listing each diagnostic. Logs go to stderr. Flags: `--root`, `--allow-writes`, `--disable-live` (the last two have nothing to change yet). |
| CLI host | `tabulartools describe` with `--detail`, `--tables`, `--types`, `--name`, `--exclude-hidden`, `--format`, `--out`. Exit codes per the architecture doc. |
| Fixture | `fixtures/pbip/ExampleSales`: a synthetic PBIP sales star schema (6 tables, 11 measures, calculation group, RLS role, M parameters, a native query) with the anti-patterns listed in ARCHITECTURE §17.1. |
| CI | `.github/workflows/ci.yml`: restore, Release build, test on `ubuntu-latest` and `windows-latest`; pack and upload the tool packages from Linux. `.gitattributes` pins LF line endings so content hashes match on both runners. |
| Packaging | `TabularTools.Cli` (command `tabulartools`) and `TabularTools.Mcp` (command `tabulartools-mcp`) .NET tool packages; installed and run locally from the packed `.nupkg` files. |

Tests: 57 (Core 30, MCP 17, CLI 10), all passing on Linux. The MCP tests start the real server process and talk to it through the SDK's client, including a check that every tool's structured content has the properties its output schema requires.

## Decisions made

- **Owner review of M0:** license MIT (ADR-0010 accepted). The other open questions (name, .NET 10, severities, differential tests, tool names, lineage scope, ADO auth) proceed with the proposed defaults; they can be revisited.
- **Test runner:** xunit.v3 4.x on Microsoft.Testing.Platform. VSTest no longer works with xunit.v3 4.x on the .NET 10 SDK, so `global.json` opts in and the test projects drop `Microsoft.NET.Test.Sdk`.
- **Tool results:** every tool returns a one-line summary and the JSON result as text blocks (for clients that only read text) plus the same JSON as structured content. Nullable fields are optional in the output schema; JSON omits nulls.
- **Expected failures are tool results, not exceptions:** a bad path or invalid TMDL returns `isError: true` with the diagnostics, without logging a stack trace.
- **CLI exit code for paths:** a missing path or a folder that isn't a model is a usage error (`2`); a model that fails to parse is `3`.
- **`TabularTools.Live` is deferred to M4**, when it gets its first code, rather than shipping an empty project.

## Known gaps

- JSON Schemas aren't yet generated into `schemas/`. The MCP server already advertises output schemas at runtime; file generation comes with the first user-authored file format (M2 rules config / M4 test files).
- No source-location index yet (object → file and line). Load errors have locations; diff and lint locations come in M2/M3.
- MCP client-provided roots aren't used yet; only `--root`.
- `tabulartools.yaml` config loading isn't implemented yet (nothing to configure in M1).
- **Windows CI hasn't run yet** at the time of writing; it runs on the first push. Results go in the next milestone notes if anything needed fixing.
- Microsoft Analysis Services DLLs are bundled in the tool packages. **Redistribution terms must be confirmed before publishing to NuGet** (ADR-0010).
