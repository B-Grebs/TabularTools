# M2 — Lint

**Status:** Done, 2026-10-28.

## What was built

| Area | What |
|---|---|
| DAX analysis | Hand-written DAX lexer (Tabular Editor token names, line/column tracking, never throws) and a model-wide dependency graph. Resolves references in measures (expression, format string, detail rows), calculated columns and tables, calculation items, RLS filters and DAX functions. Each reference records whether it's fully qualified and whether it resolved. Relationships, sort-by columns and hierarchy levels are indexed as structural uses. Variables, UDF parameters and expression-local column names (`ADDCOLUMNS`) aren't mistaken for broken references. |
| Dependencies | `DependencyQuery` walks upstream/downstream to a depth (0 = all), accepting `Table[Column]`, `[Measure]`, `'Table'`, bare names or object keys, with clear errors for ambiguous names. MCP `get_dependencies`, CLI `deps`. |
| Lint engine | Runs rulesets, applies severity overrides, disabled rules, glob suppressions (reason required) and Tabular Editor's `BestPracticeAnalyzer_IgnoreRules` annotation (on the object, its table, or the model). Reports skipped rules and per-object rule errors instead of hiding them. `failOn` decides whether the result is blocking. |
| BPA compatibility | BPA JSON accepted verbatim (plus an optional `x-tabulartools` block for severity, tags, help URL). Expressions run on `System.Linq.Dynamic.Core` over a read-only view that mirrors Tabular Editor's object model (`DependsOn`, `ReferencedBy`, `UsedInRelationships`, `RowLevelSecurity`, `Tokenize()`, …). A dialect adapter handles raw strings, `outerIt`/`current`, enum literals and token names. Regexes time out after 1 s. Only the view's own types, `RegEx`, `StringComparison` and `Object` are reachable from expressions. |
| Rulesets | `builtin` (TT001–TT005, [docs](../rules/builtin.md)); `microsoft-bpa` vendored byte-identical from `microsoft/Analysis-Services@d3ccb50` (MIT) and embedded; team BPA files by path; rules embedded in the model's `BestPracticeAnalyzer` annotation (opt-in). `scripts/update-microsoft-bpa-rules.sh` refreshes the vendored copy. |
| Config | `tabulartools.yaml` `lint:` section, found by walking up from the model to the repo root, merged with a git-ignored `tabulartools.local.yaml`. Unknown keys and bad values fail with the file and setting named. |
| MCP | `lint_model` (rulesets, minSeverity, ruleIds, config, limit), `get_dependencies`, resources `tabulartools://rulesets` and `tabulartools://rulesets/{id}`. |
| CLI | `lint` (exit 1 at `--fail-on`), `deps`, `rules list`, `rules check` (validates a BPA file without a model; exit 1 if any rule can't run). Text, Markdown (PR-comment style, grouped by severity) and JSON output. |

Tests: 143 (Core 102, MCP 23, CLI 18), all passing on Linux and Windows ([CI run](https://github.com/B-Grebs/TabularTools/actions/runs/40607541821)).

## Decisions made

- **TT003 redefined.** The architecture draft said "RLS filter references a column outside its table, or an unknown column". Referencing other tables is legitimate DAX, and unknown columns are already TT001. TT003 now flags an *unqualified* column that resolves to a different table than the one being secured, which is a real bug. ARCHITECTURE §9.1 is updated.
- **Enums are strings in the compatibility view.** BPA rules compare enums with strings (`DataType = "Double"`) and with enum literals (`DataType.Double`). Exposing strings and rewriting literals handles both.
- **String properties return "" rather than null**, matching Tabular Editor, so rules such as `FormatString.Contains("%")` don't throw on objects without a value.
- **`Object` is reachable from expressions**, for `ToString()` on enum-like values. `System.Type` isn't registered, so `GetType()` leads nowhere.
- **Unqualified column resolution** prefers the context table (calculated column, RLS), then tables named in the same expression (iterators), then a column name unique in the model. Anything else is unresolved.
- **Lint results describe each rule once** (a `rules` map) rather than repeating descriptions on every violation, to keep MCP responses small.
- **Ruleset URLs aren't supported yet.** Download the file and reference its path. Fetching remote code-like content needs an opt-in and caching design.

## Known gaps

- **Diff-aware lint** (`--base <ref>`, report only new violations) needs the M3 object matcher. The `isNew` field is reserved in the result.
- **KPI expressions** aren't analysed for dependencies, so `DependsOn` is empty for KPIs.
- **`UsedInVariations`** is computed from TOM variations but isn't covered by a fixture test.
- **Rules relying on VertiPaq statistics** (five Microsoft rules) can't fire on plain TMDL, because those annotations come from running VertiPaq Analyzer against a live model.
- **`lint --fix`** (applying `FixExpression`) is deferred until after M5, as planned.
- **JSON Schema for `tabulartools.yaml`** isn't generated yet. Unknown keys are rejected at load time instead.
