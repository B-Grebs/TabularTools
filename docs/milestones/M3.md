# M3 — Semantic diff

**Status:** Done, 2026-10-28.

## What was built

| Area | What |
|---|---|
| Git reader | `GitCliReader` behind `IGitReader` (ADR-0003): `rev-parse`, `merge-base`, `ls-tree`, one `cat-file --batch` process for all blobs, `diff --name-only` (plus untracked files for the working tree). Never fetches, checks out or writes. Refs starting with `-` are rejected. Unknown refs, missing merge bases in shallow clones, a missing `git` and non-repositories raise `GitException` with a fix hint (CLI exit code 4). Repo-relative paths come from `git rev-parse --show-prefix`, so symlinks and Windows short names don't break them. |
| Model sides | A side is a commit, the working tree (`WORKTREE`), or a folder. Commit sides write the model's blobs to a private temp folder, load them with the normal loader, and delete the folder. Without `--model`, every `*.SemanticModel` folder (and standalone `model.bim`) touched between the sides is diffed; a model present on only one side is reported as added or removed. |
| Matcher | Per type and parent scope: same name (case-insensitive) → same lineage tag (`certain`) → similarity score above `renameThreshold` (default 0.8): DAX token equality 0.95, else token Levenshtein × 0.7 + matching properties × 0.3; data columns with the same source column and type 0.9; tables by column-set Jaccard × 0.7 + partition source × 0.3; hierarchies by level columns. Greedy best-first, capped at 200 × 200. Measures match model-wide (so moves are seen). Relationships match by endpoints and follow renamed tables and columns. The matcher's base → head key map is shared with diff-aware lint. |
| Diff engine | Compares model properties, tables, columns, measures, partitions, hierarchies, calculation items, relationships, roles (RLS filters, OLS, model permission, members), shared expressions and parameters, DAX functions, perspectives and cultures. 105 change kinds, each with a default severity in one policy table (`SeverityPolicy`), listed in [docs/diff-severities.md](../diff-severities.md). Expressions that differ only in whitespace or comments are formatting-only (hidden by default, counted). Each change carries before/after values, a unified diff for expressions, rename confidence and evidence, downstream impact (transitive, from the dependency graph) and the TMDL file and line. |
| Source locations | A TMDL declaration scanner maps object keys to file and line (tables, columns, measures, partitions, hierarchies, calculation items, relationships, roles and table permissions, expressions, functions). |
| Rendering | Text, JSON (`schemaVersion: 1`) and PR-comment Markdown: counts per severity, breaking changes expanded, other severities collapsed, impact column, collapsible expression diffs. Golden files in `fixtures/diff/expected/`. |
| Diff-aware lint | `lint --base <ref>` / `lint_model baseRef`: lints the base version too and marks each violation `isNew`; violations on renamed objects stay "existing". Only new violations block. Summary counts `new` and `existing`. |
| Review | `review` = diff of every changed model + diff-aware lint of each head version, as one report. Blocking when the diff reaches `diff.failOn` or a new lint violation reaches `lint.failOn`. |
| Azure DevOps | `ado comment --file <md> --marker <key>` upserts one PR thread per marker through the REST API (7.1): finds the thread whose first comment has `<!-- tabulartools:<key> -->` and updates it, or creates one. Bodies over 140,000 characters are cut at a line, open code fences and `<details>` are closed, and a link to the run's artifacts is added. Outside PR builds it does nothing (exit 0). Behind `IPullRequestCommenter`, tested against a fake HTTP server. |
| Sample pipeline | [`samples/azure-pipelines/pr-review.yml`](../../samples/azure-pipelines/pr-review.yml) (Windows agent): full-history checkout, install the CLI, `review`, publish the report, post the comment, fail on blocking findings. |
| Config | `diff:` section in `tabulartools.yaml`: `failOn`, `renameThreshold`, `includeFormattingOnly`, `severity` overrides per kind. Unknown kinds and bad values are rejected. |
| MCP | `diff_model` (refs, `WORKTREE`, or folders; `minSeverity`, `includeFormattingOnly`, optional per-model Markdown, `limit`), `lint_model` gains `baseRef`/`mergeBase`, resource `tabulartools://diff/change-kinds`. Git errors are tool errors. |
| CLI | `diff`, `review`, `ado comment`; `lint --base`. |
| Fixtures | `fixtures/diff/ExampleSales-v1` and `-v2` (the v2 changes listed in ARCHITECTURE §17.1, plus a display-folder change and a hidden column). Tests build a temporary git repo from them with fixed authors and dates, so commit ids are stable. |

Tests: 308 (Core 246, CLI 34, MCP 28), all passing on Linux and Windows ([CI run](https://github.com/B-Grebs/TabularTools/actions/runs/40615303359)). Every v1 → v2 change is detected with its expected severity and nothing else is reported; a test fails if any change kind in the policy has no test.

## Decisions made

- **Blobs go through a temp folder** rather than TOM's in-memory `MetadataSerializationContext`. It reuses PBIP/TMDL/TMSL resolution unchanged and is easy to reason about; the folder is private and deleted immediately. ARCHITECTURE §10.1 is updated.
- **Added objects are reported once.** Columns, measures and partitions of an added or removed table are counted on the table (`"2 columns, 1 measure"`), not listed individually. Calculated tables and calculation groups report source changes on the table, not on their generated partition.
- **Severity calls not settled by the architecture draft:** role added → high; relationship removed → high, added → medium; partition added or removed on an existing table → high; shared expression removed or renamed → high (partitions break, but reports don't bind to expressions); calculation item added → info; hierarchy level changes → medium; 'assume referential integrity' → medium; role member count → high. All are overridable.
- **A partition source type change is one change** (`partition.sourceTypeChanged`, with the expression diff), not a type change plus a source change.
- **Renames that only change case** match by name and are reported as renames with evidence `name`.
- **Review lint uses the repository's config** (`tabulartools.yaml` at the repo root, or `--config`), because a commit side has no folder of its own to search from.
- **Git commands time out** after 2 minutes and never inherit stdin. The first Windows CI run hung in the test step with no logs; with these limits the next run passed, and any future hang fails with the command named.
- **The PR comment marker is validated** (letters, digits, `-`, `_`, `.`), so it can't close the HTML comment early.
- **New threads are `active` by default**; `--status closed` posts them resolved, for teams whose branch policy requires resolving comments.

## Known gaps

- **Not compared yet:** annotations, per-object translations, perspective membership, KPI details beyond added/removed, refresh policies and calendars. Listed in docs/diff-severities.md.
- **Affected reports** (`impact.reports`) need lineage (M5); the field is reserved.
- **Diff locations for `model.bim`** models are empty (no line index for TMSL).
- **Measure tests and lineage** aren't part of `review` yet (M4, M5).

## Unverified

- **Azure DevOps REST calls** were not run against a real organization (none available from the build environment). They follow the documented 7.1 API — list threads, create a thread, update a comment — and are tested against a fake server, including URL escaping of project names and the error hint for 401/403.
- **The sample pipeline** was checked for valid YAML only. Things to confirm on first use: that `origin/<target>` exists after the PR checkout with `fetchDepth: 0`, and that the build service has *Contribute to pull requests*.
