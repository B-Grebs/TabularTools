# M4 — Measure tests

**Status:** Done, 2026-10-28. Offline parts tested on Linux; **live parts unverified** (no tenant, and `api.powerbi.com` is blocked from the build environment). Run [`scripts/verify-live.ps1`](../../scripts/verify-live.ps1) to verify them.

## What was built

| Area | What |
|---|---|
| Test files | `*.measuretests.yaml` ([schema](../../schemas/measure-tests.schema.json)): model, profile, default filters and tolerance, cases with measures, group-by columns, filters, an RLS role, and `differential`, `invariant` and `snapshot` assertions. Strict loading: unknown keys, duplicate ids, missing `expr`/`rows` and ragged snapshot rows are errors with the file and case named. Snapshot rows keep YAML types (`2023` is a number, `"2023"` text). |
| Case resolution | Measures, columns, filters, invariants and roles are checked against the head model before any query runs; problems make that case `error`, not the whole run. |
| Override plan | From the M3 matcher: measures whose DAX changed (formatting-only excluded) are **directly edited**; renamed, added and removed measures are defined on their side so each side's queries can name them; moved-only measures keep their model definition. Calculated column changes use `DEFINE COLUMN` only with `tests.columnOverrides: true`. Every diff change kind is classified as simulated, not simulated (listed as *structural, not tested*), or without effect on values; a test fails if a new high-severity kind isn't classified. |
| Query planner | `CALCULATETABLE(SUMMARIZECOLUMNS(…), filters) ORDER BY …` with a `DEFINE` block. Each query defines only the overrides it depends on (transitively, via the dependency graph), so an unrelated change, such as a new measure on a new table, can't break it. Identical base and head queries run once. Invariants are a separate query returning the rows where the condition is false, among rows where any case measure has a value. |
| Comparison | Row by row on the group-by key, never by position; missing rows count as BLANK; numbers match within `max(absolute, relative × |b|)`; a number never equals text. A change on a directly edited measure is `changed` (expected); on any other measure it's `fail` (regression). Head query failing while base runs is `fail`; both failing is `error`. |
| Executors | `IDaxExecutor` port in Core. `RecordedDaxExecutor` (Core) replays `*.recordings.yaml` keyed by SHA-256 of the canonical query and role, and fails naming the case when a query isn't recorded. `RecordingDaxExecutor` captures a live run for replay (`test run --record`). `XmlaDaxExecutor` (new `TabularTools.Live` project) runs queries with ADOMD.NET and an access token, refreshed through `OnAccessTokenExpired`; engine errors are per-query, connection and sign-in errors are environment errors (exit 4). |
| Safety | `DaxQueryGuard` lets through only DAX queries (first keyword `DEFINE`/`EVALUATE`, at least one `EVALUATE`) and `SELECT … FROM $SYSTEM.<view>` DMVs; TMSL, XMLA, `;`-separated statements and DMX keywords are rejected before a token is requested. Endpoints must be `powerbi://`/`asazure://` on `*.powerbi.com`, `*.asazure.windows.net` or `live.allowedHosts`; local engines (`localhost:<port>`, `desktop`) only on Windows. `live.allowRunDax: false` turns off ad-hoc queries. |
| Auth | Profiles name an auth mode: `default` (environment → workload identity → Azure CLI → browser on Windows outside CI), `azureCli`, `servicePrincipal`, `interactive`, `deviceCode` (instructions on stderr), `token` (from an environment variable named by `tokenEnv`), `none` (local engines only). |
| Writes | `FileWriter`, the single write path (ARCHITECTURE §14.3): confined to roots (`..` and symlink escapes refused), atomic, keeps CRLF and BOM, dry run by default, reports a unified diff per file. |
| Generator | `test gen` / `generate_measure_tests`: canonical names, a readable default id, differential or snapshot (captured through the profile). Appends to an existing file keeping its comments when `cases:` is the last key; replacing a case rewrites the file and warns that comments are lost. |
| Config | `profiles` (endpoint, database, auth, tokenEnv, or recordings), `tests` (files, profile, tolerance, columnOverrides, strict, maxParallel, timeoutSeconds), `live` (allowRunDax, allowedHosts). Local config replaces profiles by name. Profile precedence: argument → `TABULARTOOLS_PROFILE` → test file → `tests.profile`. |
| CLI | `test run` (exit 1 on fail/error, or changed with `--strict`), `test gen`, `dax`; `review` runs the configured tests (`--no-tests`, `--profile`, `--strict`, `--json-out`). |
| MCP | `run_measure_tests`, `generate_measure_tests` (previews; saves only with `--allow-writes`), `run_dax` (not registered with `--disable-live`, which also limits tests to recordings). Resources `tabulartools://schemas/measure-tests` and `tabulartools://workspace/test-files`. |
| Rendering | Text, JSON and a PR-comment section: non-passing cases in a table, value differences (regressions marked), and untested structural changes. Golden file `fixtures/diff/expected/ExampleSales.tests.md`. |
| Pipeline sample | `pr-review.yml` runs `review` once (Markdown plus `--json-out`), inside `AzureCLI@2` when `SERVICE_CONNECTION` is set so tests can sign in with workload identity federation. |
| Fixtures | `fixtures/pbip/ExampleSales/tests/` (config with a recorded profile, test file, recordings) and `fixtures/diff/tests/` (v1 → v2 differential: one regression, one expected change, a renamed and a moved measure that pass). Recordings are hand-written values; `UPDATE_GOLDEN=1` rewrites their query text from the planner. `fixtures/live/LiveCheck.SemanticModel`: a data-source-free model for live verification. |

Tests: 472 (Core 368, Live 21, CLI 48, MCP 35), all passing on Linux and Windows ([CI run](https://github.com/B-Grebs/TabularTools/actions/runs/40620156439)); one live test is opt-in and skipped by default.

## Decisions made

- **Overrides are per query, not per run.** Defining every changed measure in every query would break all queries as soon as one change can't be evaluated against the deployed model (v2's new `Promotion` table showed this). Each query now carries only what its measures depend on.
- **Moved measures aren't overridden.** The table doesn't change a measure's value, and defining it on its new table may clash with the deployed model's measure of the same name. The verification script records how the service reacts.
- **Calculated column overrides are opt-in** until `DEFINE COLUMN` on an existing column is verified (R3).
- **`RecordedDaxExecutor` lives in Core**, not Live, so offline runs (CI, MCP with `--disable-live`) need neither ADOMD.NET nor Azure.Identity.
- **`generate_measure_tests` is always registered**; it previews by default and only saves with `--allow-writes`. ARCHITECTURE §14.1 is updated.
- **Default base is `HEAD`, default head the working tree**, so `test run` with no options tests uncommitted edits. Outside a git repository, differential assertions are skipped with a note and the rest runs.
- **Snapshot assertions run with the head overrides**, so a snapshot fails when the change alters a pinned value, which is its purpose. Capturing (`test gen --mode snapshot`) uses the deployed definitions.
- **Device code was dropped from the default auth chain**: it would wait forever on a build agent. It stays available as `deviceCode`.
- **Engine errors are exit 2 for `dax`** (the query is wrong), while sign-in and connection failures are exit 4.
- **`--record` captures full results**; the row cap is applied on replay.

## Live verification

Not run yet. Deploy `fixtures/live/LiveCheck.SemanticModel` ([how](../../fixtures/live/README.md)), then on Windows:

```powershell
./scripts/verify-live.ps1 -Endpoint 'powerbi://api.powerbi.com/v1.0/myorg/<workspace>'
```

Paste the report here. It answers:

| Question | Why it matters |
|---|---|
| Does XMLA over HTTPS work with our own token? | Everything live depends on it. |
| Do model measures pick up a query-scoped override of a measure they use (R3)? | Differential tests rely on it. If not, the planner must also override dependents. |
| Can `DEFINE COLUMN` redefine an existing calculated column (R3)? | Decides whether `tests.columnOverrides` can be on by default. |
| Does a query measure clash with a model measure of the same name on another table? | Decides whether moved measures could be overridden. |
| Do RLS roles, the row cap, the guard, and a full recorded test run and offline replay work? | End-to-end check of the shipped features. |

The script was exercised here against an emulated engine (the real CLI with a fake executor answering LiveCheck's queries), which caught and fixed one bug in the script itself; that proves its logic, not the service.

## Known gaps

- **Sovereign clouds** (`powerbigov.us`, `powerbi.cn`) can be allowed with `live.allowedHosts`, but the token scope is always the public cloud's.
- **Power BI Desktop** (`endpoint: desktop`) picks the most recently started instance; there's no way to choose among several yet.
- **DAX user-defined function changes** aren't simulated (`DEFINE FUNCTION`); they're listed as not tested.
- **Calculation group changes** can't be simulated in a query and are listed as not tested.
- **Measure-level errors** inside a query fail the whole query; the result names the case, not the measure.
- **Test files are read from disk** even when `--head` is a git ref; only the model comes from the ref.
- **Recordings** match on the exact query text, so a planner change invalidates them (CI tests catch this; `UPDATE_GOLDEN=1` fixes fixtures, `--record` re-captures real ones).
- **JSON Schema for `tabulartools.yaml`** still isn't generated (as in M2).
